# Picabia seams in upstream FigCraft files

Every edit Picabia makes to a file that comes from upstream FigCraft is a *seam*: as few lines as
possible, calling into Picabia code, marked `// PICABIA: <reason>` (`rg "PICABIA:"` lists them).
When an upstream merge conflicts, resolve it seam by seam with this table, then run `cargo xtask ci`.

| File | Function / item | Why | How to re-apply |
|---|---|---|---|
| `.github/workflows/release.yml`, `sonarcloud.yml`, `freebsd.yml`, `windows-arm64.yml` | top job | Need storytold signing secrets, SonarCloud token or its runners/schedules | Re-add `if: github.repository == 'storytold/figcraft'` under the job name (4 lines in all). `ci.yml`, `nix.yml`, `packaging-lint.yml` call public reusable workflows and run unchanged on GitHub-hosted runners. |
| `Cargo.toml`, `Cargo.lock` | craft-libs `rev` pins (8 lines + lock) | Upstream's pin `92d392cf` has a workspace manifest that current cargo refuses (`craft-menu` fails to load), so nothing builds. Bumped to `e11f9d9a`, the rev the upstream developer's tree uses | Drop this seam as soon as upstream's own pin builds again: take upstream's rev. Otherwise `sed` the old rev to the new in both files |
| `Cargo.toml` | `[workspace.dependencies]` | Workspace dependency for the new `figcraft-modifiers` crate (members already glob `crates/*`) | Re-add `figcraft-modifiers = { path = "crates/modifiers" }` after `figcraft-plugin`, with its `# PICABIA:` comment |
| `xtask/src/layers.rs` | `TABLE` | `figcraft-modifiers` is layer 2 (deps: geom, doc) | Re-add `("modifiers", 2),` after `("plugin", 2),`, with its `// PICABIA:` comment |
| `assets/app-icon/*` (`figcraft.svg`, `figcraft-small.svg`, rendered PNGs/`.ico`/`hicolor/`, `README.md`, `LICENSE.txt`), `ATTRIBUTION.md` row | App icon | Replaces FigCraft's chameleon with Picabia's original placeholder (eight dots on a ring). File names stay FigCraft's so `cargo xtask icon`, `include_bytes!` paths and packaging need no edits. About window, rail logo-less icon and `theme::paint_app_icon` pick it up for free | Keep ours on conflict. Edit the two SVGs, run `cargo xtask icon` (needs `resvg`), update the README/ATTRIBUTION row |
| `apps/figcraft/src/main.rs`, `startup.rs`, `services.rs` + new `apps/figcraft/src/picabia.rs` | `--version`, viewport title and app id, `run_native` name, macOS app menu, startup error dialog title, `config_dir()` | App name "Picabia", Wayland/X11 id `org.picabia.Picabia`, config folder `Picabia` (preferences, `Recovery`, `Plugins`) so Picabia and FigCraft don't share state | Re-point the strings at `picabia::APP_NAME` / `APP_ID` / `CONFIG_DIR`; the constants live only in `picabia.rs` (ours) |

The 4 changed catalog keys are renamed in `en.toml` and the old translations removed from the other 22 locales (the i18n test needs `en` to match the code) | Re-apply the 3 strings in `dialogs.rs` and `toolbar.rs`, then rename keys in `en.toml` and delete the stale keys from other locales until `cargo test -p figcraft-ui-egui i18n` passes |
| `crates/ui-egui/src/theme.rs` | `paint_wordmark` | Wordmark reads "Pica" + accent "bia" (About window, home screen) | Change the two strings |
| `crates/ui-egui/src/icons/draw.rs` | `Icon::Logo` | In-app logo glyph (main menu button) is Picabia's ring of dots, not FigCraft's chameleon tail | Keep ours; `arc_pts`/`FRAC_PI_2` may become unused upstream, then remove the import |
| `apps/figcraft/build.rs` | Windows resource strings | ProductName/FileDescription "Picabia", CompanyName "Picabia contributors" | Re-set the three strings |
| `apps/figcraft-web/index.html` | `<title>`, loading text | Browser tab name | Replace the two strings |
| `packaging/macos/Info.plist.in` | display name, name, `CFBundleIdentifier` (`org.picabia.Picabia`), copyright | macOS bundle identity. Executable and icon file names (`FigCraft`) and the UTI/URL scheme stay so `package.sh` is unchanged | Re-set those 4 values |
| `packaging/linux/ai.storyteller.figcraft.desktop` | `Name`, `StartupWMClass` | Name "Picabia"; window class matches the app id so the window groups with the launcher. File name, `Icon=`, metainfo, mime and Flatpak ids are deferred (renaming 7+ files) | Re-set the two values |

If upstream adds another `Clipboard { .. }` literal, add the field there too (the compiler points at it) |
